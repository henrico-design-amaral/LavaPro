# GitHub Pages static validation demo

## Why this is a static demo

GitHub Pages is documented by GitHub as static site hosting for HTML, CSS and JavaScript files from a repository. Source: [GitHub Docs - About GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/about-github-pages).

For that reason, the LavaPro Pages layer lives separately in `docs/site/` and contains only:

- `index.html`
- `styles.css`
- `app.js`

It uses mock data based on `prisma/seed.ts`:

- 1 business
- 8 customers
- 10 vehicles
- 6 services
- 8 products
- 12 orders
- 34 stock movements

## Why the full MVP cannot run on GitHub Pages

The functional LavaPro MVP is an offline-first local application built with Next.js, Prisma and SQLite. That app requires local execution for database access, mutations and server-side code.

GitHub Pages does not provide an application server for Prisma, SQLite writes or Next server actions. Next.js documents server functions/actions as server-side execution, and its static export documentation lists Server Actions as unsupported for static export. Sources: [Next.js `use server`](https://nextjs.org/docs/app/api-reference/directives/use-server) and [Next.js static exports](https://nextjs.org/docs/app/guides/static-exports).

Therefore, this repository must not attempt to deploy the functional MVP to GitHub Pages. The Pages deployment is only a validation demo.

## How to publish via GitHub Pages

The workflow `.github/workflows/pages.yml` deploys `docs/site` using GitHub Actions. GitHub documents custom Pages workflows with the Pages actions `configure-pages`, `upload-pages-artifact` and `deploy-pages`. Source: [GitHub Docs - Using custom workflows with GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

Steps:

1. Push this branch to GitHub.
2. In the repository settings, enable GitHub Pages with GitHub Actions as the source.
3. Run the `Deploy static demo to GitHub Pages` workflow, or push to the configured branch.
4. Open the Pages URL generated by the workflow.

## What the demo validates

- Visual presentation of the operational cockpit.
- Navigation across the key MVP screens.
- Dashboard metrics calculated from mock data.
- Queue status lanes.
- Orders table and status states.
- New order preview with planned stock usage.
- Customers and vehicle coverage.
- Services with prices, durations and product usage.
- SmartStock inventory alerts and stock movements.
- Daily report revenue, cost, margin, ticket average and service mix.

## What still requires local MVP execution

- Real SQLite persistence.
- Prisma queries and mutations.
- Next.js server actions.
- Real order creation, status changes and stock writes.
- Local offline-first validation with `npm run dev`.
- Production build validation with `npm run build`.

For the functional MVP, run:

```bash
npm install
npm run db:push
npm run db:seed
npm run dev
```
